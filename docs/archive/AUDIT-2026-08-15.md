## 6. Incident: deletion of the platform tenant + shared bank

**Timeline**
- 03:10 engine-live passed with shared bank n=784, platform tenant present.
- Afterwards, a tenant-cleanup statement
  `delete from tenants t where not exists (select 1 from tenant_memberships ...) and t.name like '%Workspace' ...`
  ran on live. The platform tenant has **no `tenant_memberships` rows** (platform admins
  live in `platform_admins`), so it is matchable by the zero-membership clause; its live
  name/state (partial DB) matched the cleanup pattern. `questions_tenant_id_fkey` is
  `ON DELETE CASCADE`, so the tenant deletion cascaded.
- Observed loss: platform tenant row, 11 exams, all subjects/chapters/topics,
  `exam_patterns`, `subscriptions`, `platform_admins`, the 8 demo questions, and the
  ~784-question shared bank. Survived: `question_sources`, `roles`, `question_types`,
  and all `%Workspace` tenants.
- Audit trail: `audit_logs` contains no tenant/exam records for the event (no forensics).

**Root-cause note (honest, unresolved)**
- The cleanup predicate required `name like '%Workspace'`. The repo seed names the platform
  tenant `ExamPro Platform`, which does not match — but the live DB was a partial/older
  state (only 7 exams instead of the seed's 11), so its exact tenant name could not be
  confirmed after deletion. The cleanup remains the only tenant-deleting statement in the
  deletion window, but the name-match is unproven.

**Restoration (completed)**
- Re-created platform tenant row and re-applied the idempotent seeds on live:
  `0009_seed.sql` (tenant, 11 exams, 10 subjects, 193 chapters, 7 exam_patterns,
  subscriptions), `0017_demo_seed.sql` (8 demo MCQs, VERIFIED/DEMO, fully linked),
  `0020_demo_syllabus.sql` (demo chapters/topics + question links).
- Verified: tenant row ACTIVE; counts exams=11, subjects=10, chapters=193, topics=8,
  questions=8 (options/answers/solutions present), exam_patterns=7, subscriptions=1.

**Loss (documented, per user decision — no backup available)**
- The ~784-question shared bank is **not recoverable**: source `build/dataset/v1/shards/*.json.gz`
  no longer exists on this machine (exhaustive search of `C:\Users\Dell` for `*.json.gz`,
  shard/dataset dirs, zips, dumps, backups; only unrelated Shopify plugin gz files found).
  `sample-questions/questions.json` holds only ~14 questions. No DB backup was provided.
- Impact on verification (by cause, not regression):
  - engine-live §5 `student can read shared platform question bank` — n=8, requires n>100.
  - engine-live §7 `app_data_quality` total=38, requires total>=700.
  - All Playwright tests remain green because they generate count=5 papers, which the
    restored 8 demo questions satisfy.
- **Action needed from owner:** re-import a production dataset via
  `supabase/import-dataset.mjs` once shards are available (idempotent), or restore from a
  Supabase PITR/backup and re-apply migrations 0026/0027.
